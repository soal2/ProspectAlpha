# 现金流分析器（Cashflow Analyzer）

对港股 IPO 发行人进行 **10 维度**现金流可持续性评估，覆盖现金流结构、盈利质量、经营造血、资本支出、融资依赖、现金跑道、营运效率、偿债能力和行业对标。附带**趋势方向判断**和**跑道敏感性分析**。

## 设计理念

传统的现金流分析通常只关注"现金跑道还剩几个月"这单一指标。本 skill 将评估扩展到 **10 个维度**，分为三大类：

| 类别 | 维度 | 核心问题 |
|---|---|---|
| **现金流**（R0-R6） | 经营造血、盈利质量、自由现金流、资本支出、融资依赖、现金跑道、现金流结构 | 钱从哪里来？花到哪里去？能撑多久？ |
| **营运与偿债**（R7-R8） | 营运资金效率、偿债能力 | 资金周转快不快？到期债务还不还得起？ |
| **行业对标**（R9） | 行业基准偏离度 | 和同行比，这些指标正常吗？ |

每个维度不仅仅是"是否超标"的二元判断，还包含：

- **趋势方向**（R0/R1/R2/R7）：指标是在改善还是恶化？同样的负值，收窄中 vs 扩大中结论完全不同
- **多期连续检测**（R0/R1/R2）：负值是偶发一期还是连续多期的结构性问题？
- **敏感性分析**（R5）：如果烧钱速度加快 20%，跑道还剩多久？
- **行业差异化**（R4/R9）：SaaS 公司亏损经营是常态，地产公司高杠杆是行业特征，用统一标准衡量会误判

## 触发场景

- 用户询问某只新股的现金流是否健康、是否存在现金流风险
- 需要一键扫描现金流风险并给出明确结论（"存在现金流风险"或"暂未识别现金流风险"）
- 招股书中出现了连续亏损或经营现金流为负的公司，需要判断这是短期阵痛还是结构性失血
- 需要计算公司的现金跑道（还能烧几个月），以及在不同烧钱速度下的敏感性情景
- 需要按行业对标判断现金流指标是否偏离同行（例如 SaaS 的亏损经营 vs 地产的高杠杆）
- 作为 orchestrator 管线中的现金流维度，输出加权评分

## 快速开始

```bash
# 1. 一键风险检查，输出结论（推荐）
python "<skill-dir>/scripts/analyzer.py" --check

# 2. 无风险场景验证（健康公司 demo）
python "<skill-dir>/scripts/analyzer.py" --check --healthy

# 3. 行业对标 + 敏感性分析
python "<skill-dir>/scripts/analyzer.py" --check --industry saas --sensitivity

# 4. 完整 10 维风险扫描（JSON 格式，含全部正常项）
python "<skill-dir>/scripts/analyzer.py" --risk-scan --json

# 5. 自定义单期分析（单位：百万港元），含扩展字段
python "<skill-dir>/scripts/analyzer.py" \
  --cash 2400 --op-cf -800 --inv-cf -200 --fin-cf 1500 \
  --revenue 1200 --ebit -200 --interest -40 \
  --st-debt 300 --total-debt 1000 \
  --industry 医药 --sensitivity --json
```

> `<skill-dir>` 指本 `SKILL.md` 所在的目录。

## 10 维度风险指标详解

风险等级：**预警 > 关注 > 正常 > 数据不足**。综合风险取所有指标的最差状态。

---

### R0 — 经营造血能力

**回答什么问题**：公司的主营业务是否在真正赚钱（产生现金）？

**检测逻辑**：

1. **连续负值检测**：经营现金流是否连续多期为负。连续 ≥3 期为"预警"，连续 ≥2 期为"关注"
2. **趋势方向**（多期数据时自动启用）：OpCF 序列是在改善（负值收窄）还是恶化（负值扩大）。如果趋势恶化，即使只有 2 期为负也会升级为"预警"
3. **OpCF/营收比率**（如果提供了 `revenue` 字段）：经营现金流占营收的百分比。健康企业通常 > 5%，如果为负则说明每一元营收都在消耗现金

**为什么重要**：港股 IPO 最常见的"变脸"模式——上市前营收高增长，上市后经营现金流突然转负。R0 是第一个也是最重要的防线。

**需要的额外字段**：`revenue`（可选，用于计算 OpCF/营收比率）

---

### R1 — 盈利质量

**回答什么问题**：账面上的净利润是真实的现金利润，还是"纸面利润"？

**检测逻辑**：

1. **CF/NI 背离度**（经典指标）：经营现金流 / 净利润。如果这个比值 < 0.5，说明每赚 1 元净利润只收回了不到 5 毛的现金——其余可能是应收账款或会计处理
2. **营收-OpCF 增速背离**（新增，多期数据时自动启用）：如果营收增长了 15% 以上但经营现金流增速不到 5%，这是经典的"纸面利润"红旗信号。公司可能在通过放松信用政策（延长账期）来粉饰营收增长

**为什么重要**：港股历史上多次出现"利润很好看但现金流很差"的财务造假案例。R1 的营收-CF 背离检测专门针对这类情况。

**需要的额外字段**：`net_income`（净利润）、`revenue`（可选，用于增速背离检测）

---

### R2 — 自由现金流

**回答什么问题**：扣除必要的资本支出后，公司真正剩下了多少可自由支配的现金？

**检测逻辑**：

1. **连续负值检测**：FCF = 经营现金流 - |资本支出|。连续 ≥3 期为负 → "预警"，连续 ≥2 期为负 → "关注"
2. **趋势方向**：FCF 是在改善还是恶化？趋势恶化时升档处理
3. **FCF/营收比率**（如果提供了 `revenue`）：衡量每一元营收能产生多少自由现金

**为什么重要**：FCF 是分红、回购、再投资的真正来源。如果一家公司经营现金流为正但 FCF 持续为负，说明它需要不断投入资本支出来维持现有业务——这是重资产模式的典型特征。

**需要的额外字段**：`capex`（资本支出）、`revenue`（可选）

---

### R3 — 资本支出合理性

**回答什么问题**：公司的投资扩张是否超出了自身造血能力的支撑范围？

**检测逻辑**（三维度综合）：

1. **Capex / OpCF 比率**：资本支出与经营现金流的比值。> 2.0 为"关注"，> 3.0 为"预警"。如果经营CF为负，任何 capex 都会触发关注
2. **投资强度**：|投资活动现金流| / 总资产。> 15% 为"关注"，> 30% 为"预警"
3. **维持性 vs 扩张性 Capex 分类**（如果提供了 `depreciation`）：扩张性 Capex = |总Capex| - 折旧。如果扩张性 Capex / OpCF > 1.5，说明公司正在用外部融资支撑激进扩张

综合取三项中最差状态。

**为什么重要**：很多 IPO 公司将募资用于"扩张"但实际是填补经营窟窿。区分维持性和扩张性资本支出，可以看出公司是在"修天花板"还是"补地板"。

**需要的额外字段**：`capex`、`total_assets`、`depreciation`（可选，用于 capex 分类）

---

### R4 — 融资依赖度

**回答什么问题**：如果没有外部融资输血，公司能活多久？

**检测逻辑**：

Financing CF / 期末现金余额。> 1.5 为"关注"，> 2.0 为"预警"。同时与行业基准进行比较：如果偏离超过 3 倍，附加"严重偏离行业"警示。

如果融资 CF 为负（公司在偿还债务或分红），这反而是健康信号。

**为什么重要**：IPO 本身就是一次大规模的融资事件。如果 IPO 前公司的现金流高度依赖融资，那么 IPO 后融到的钱能撑多久就是关键问题。

**需要的额外字段**：`industry`（可选，用于行业比较）

---

### R5 — 现金跑道

**回答什么问题**：现有现金能撑多久？

**检测逻辑**：

1. 月均消耗 = |经营CF + 投资CF| / 期间月数
2. 现金跑道 = 现金及等价物 / 月均消耗
3. < 12 个月 → "预警"，< 24 个月 → "关注"

**敏感性分析**（默认附带）：

在三种烧钱速度下分别计算跑道：

- **乐观情景**：月均消耗 × 0.8（消耗减速 20%）
- **基准情景**：月均消耗（当前速度）
- **悲观情景**：月均消耗 × 1.2（消耗加速 20%）

如果三种情景下的跑道差异很大，说明公司对烧钱速度高度敏感，经营杠杆风险大。

**为什么重要**：跑道是投资人最关心的数字。敏感性分析让用户看到"如果融资环境变差"时的最坏情况。

---

### R6 — 现金流结构（新增）

**回答什么问题**：公司的现金流是"自己赚的"还是"别人给的"？

**检测逻辑**：

计算三大现金流的绝对值占比：

- 经营CF占比 = 经营CF（正值部分）/ (|经营CF| + |投资CF| + |筹资CF|) × 100%
- 筹资CF占比 = |筹资CF| / 总规模 × 100%
- 投资CF占比 = |投资CF| / 总规模 × 100%

判定标准：

| 经营CF占比 | 状态 |
|---|---|
| ≥ 50% | 正常（造血结构健康） |
| 30% ~ 50% | 关注（造血能力偏弱） |
| < 30% | 预警（高度依赖外部资金） |

额外检测：如果筹资CF占比 > 60% 且经营CF ≤ 0 → 升级为"预警"（完全依赖融资输血）。

**为什么重要**：这是本次升级的核心新增指标。三流结构一眼就能看出公司的现金流"基因"——是靠经营赚钱（健康），靠融资续命（危险），还是靠变卖资产（不可持续）。

---

### R7 — 营运资金效率（新增）

**回答什么问题**：公司的钱被"卡"在应收账款和存货里多久？

**检测逻辑**：

先计算三个周转指标：

- **DSO**（应收账款周转天数）= 应收账款 / 营收 × 365 —— 卖出去的东西多久能收到钱
- **DIO**（存货周转天数）= 存货 / 营业成本 × 365 —— 存货在仓库里躺多久
- **DPO**（应付账款周转天数）= 应付账款 / 营业成本 × 365 —— 欠供应商的钱多久才付

然后计算 **CCC**（现金转换周期）= DSO + DIO - DPO

判定标准：

| CCC 变化 | 状态 |
|---|---|
| 较首期恶化 > 30 天 + 趋势恶化 | 预警（营运效率严重下滑） |
| 较首期恶化 > 15 天 | 关注 |
| CCC > 60 天 + 趋势恶化 | 关注 |

**为什么重要**：DSO 突然拉长往往是渠道压货或放宽信用政策的结果——营收数字好看但现金回不来。IPO 前夕如果 DSO 急剧上升，需要高度警惕。

**需要的额外字段**：`revenue`、`accounts_receivable`、`inventory`、`cogs`、`accounts_payable`（缺任意一个 → "数据不足"）

---

### R8 — 偿债能力（新增）

**回答什么问题**：到期债务还不还得起？会不会出现流动性危机？

**检测逻辑**（三维度综合）：

**子项 A — 利息覆盖倍数** = EBIT / |利息支出|

| 倍数 | 状态 |
|---|---|
| < 1.5x | 预警（利润连利息都覆盖不了） |
| < 3.0x | 关注 |
| ≥ 3.0x | 正常 |

**子项 B — 短期负债比** = 短期借款 / 现金储备

| 比值 | 状态 |
|---|---|
| > 3.0x | 预警（短期债务远超现金，流动性危机） |
| > 1.5x | 关注 |
| ≤ 1.5x | 正常 |

**子项 C — 债务偿还年限** = 总有息负债 / 经营CF

| 年限 | 状态 |
|---|---|
| > 10 年 | 预警（靠经营现金流要 10 年以上才能还清） |
| > 5 年 | 关注 |
| ≤ 5 年 | 正常 |

综合取三项中最差状态。

**为什么重要**：这是港股 IPO 最致命的红线之一。很多公司在上市前夕大量举债，如果利息覆盖不足或短期债务远超现金，上市后可能迅速暴雷。

**需要的额外字段**：`ebit`、`interest_expense`、`short_term_debt`（缺任意一个 → "数据不足"），`total_debt`（可选，用于偿还年限）

---

### R9 — 行业对标（新增）

**回答什么问题**：和同行业公司相比，这些指标正常吗？

**检测逻辑**：

根据 `industry` 标签选择行业基准，比较以下指标：

1. **OpCF 利润率**（vs 行业 OpCF 利润率基准）
2. **DSO**（vs 行业 DSO 基准）
3. **融资依赖度**（vs 行业融资依赖基准）
4. **FCF 利润率**（vs 行业 FCF 利润率基准）

如果某指标偏离行业基准超过 2 倍，记录偏离方向和幅度。

**重要**：R9 始终为"提示性"指标——即使严重偏离，最高也只到"关注"级别，不会独立触发"预警"。这是因为它反映的是"与同行的差异"而非"绝对风险"。一家 SaaS 公司的 OpCF 利润率为 -60% 可能远比行业基准 -5% 差，但这不一定意味着它比同行更危险——可能只是处于更早期的增长阶段。

**需要的额外字段**：`industry`（标签字符串：`saas` / `医药` / `金融` / `地产` / `消费`），以及各相关指标的基础字段

---

## 行业基准详解

不同行业的现金流特征差异巨大，使用统一阈值会严重误判。本 skill 内置了 5 个行业的差异化基准：

| 行业 | OpCF利润率 | Capex/营收 | DSO(天) | CCC(天) | 利息覆盖 | 负债/现金 | 融资依赖 |
|---|---|---|---|---|---|---|---|
| **SaaS** | -5% | 8% | 60 | 45 | 5.0x | 0.5x | 1.0x |
| **医药** | -15% | 12% | 90 | 120 | 2.0x | 0.8x | 1.5x |
| **金融** | 30% | 3% | 15 | 10 | 3.0x | 2.0x | 0.5x |
| **地产** | 10% | 20% | 60 | 200 | 2.5x | 2.5x | 1.0x |
| **消费** | 12% | 6% | 25 | 35 | 8.0x | 0.3x | 0.3x |
| **通用** | 10% | 8% | 45 | 60 | 4.0x | 1.0x | 0.8x |

**各行业特征解读**：

- **SaaS**：允许负 OpCF 利润率（早期获客成本高），但要求较高的利息覆盖（轻资产、低负债），DSO 容忍度较高（年合同制常见）
- **医药**：OpCF 利润率可低至 -15%（研发期长），CCC 容忍度最高（临床试验周期长），融资依赖容忍度最高（Biotech 常态）
- **金融**：高 OpCF 利润率（息差收入），极低 Capex（非重资产），负债/现金比可有 2.0x（银行业杠杆经营特征）
- **地产**：高 Capex（项目开发），极长 CCC（项目周期 200 天+），高负债/现金比（行业高杠杆特征）
- **消费**：稳定正利润率和低负债（现金流充沛特征），DSO 短（即时消费），利息覆盖高（低杠杆）

## API

### `CashflowAnalyzer()`

| 方法 | 返回值 | 说明 |
|---|---|---|
| `check_risk(data, ticker="")` | `dict` | **推荐**。执行 10 维扫描并输出结论，返回 `has_risk`、`conclusion`（存在现金流风险 / 暂未识别现金流风险）、`risks`（仅含预警+关注项）、`all_indicators`（全部 10 项）、`risk_counts` |
| `risk_scan(data, ticker="")` | `dict` | 执行全部 10 维扫描，返回 `overall_risk`、`risk_counts`、`indicators`（全部 10 项）、`periods_analysed` |
| `calculate_runway(data, include_sensitivity=False)` | `dict` | 计算现金跑道（月数），返回 `runway_months`、`monthly_burn_rate`、`total_cashflow`、`status`。设置 `include_sensitivity=True` 时额外返回 `sensitivity`（乐观/基准/悲观三种情景） |

### 输入字段一览

支持单期 `{"cash_and_equivalents": ..., "operating_cashflow": ..., ...}` 或多期 `{"periods": [...]}`。

**核心字段**（必填）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `cash_and_equivalents` | float | 现金及等价物（百万港元） |
| `operating_cashflow` | float | 经营活动现金流净额 |
| `investing_cashflow` | float | 投资活动现金流净额 |
| `financing_cashflow` | float | 筹资活动现金流净额 |
| `period_months` | int | 期间月数（默认 12） |

**扩展字段**（可选，缺失 → 对应指标显示"数据不足"）：

| 字段 | 影响的指标 | 说明 |
|---|---|---|
| `net_income` | R1 | 净利润 |
| `capex` | R2, R3 | 资本支出 |
| `total_assets` | R3 | 总资产 |
| `revenue` | R0, R1, R2, R7 | 营业收入 |
| `accounts_receivable` | R7 | 应收账款 |
| `inventory` | R7 | 存货 |
| `accounts_payable` | R7 | 应付账款 |
| `cogs` | R7 | 营业成本 |
| `ebit` | R8 | 息税前利润 |
| `interest_expense` | R8 | 利息支出（通常为负值） |
| `short_term_debt` | R8 | 短期借款 / 一年内到期债务 |
| `total_debt` | R8 | 总有息负债 |
| `depreciation` | R3 | 折旧（用于区分维持性 vs 扩张性 Capex） |
| `industry` | R4, R9 | 行业标签：`saas` / `医药` / `金融` / `地产` / `消费` |

> **提示**：提供的字段越多，分析覆盖越完整。只提供核心 4 字段时，R0-R6 均可正常工作（R1 需 `net_income`），R7-R9 将显示"数据不足"。

## 输出示例

### check_risk() — 有风险（SaaS 烧钱型，多期数据）

```json
{
```

## 决策指南

### 如何解读结论

| 结论 | 含义 | 建议行动 |
|---|---|---|
| **存在现金流风险**（预警项 ≥ 1） | 至少有一个维度触发红色警报 | 逐项检查 `risks` 数组中的详情，重点关注"预警"级别的指标 |
| **存在现金流风险**（仅有关注项） | 没有红色警报，但有黄灯信号 | 结合行业基准判断是否需要关注，关注项可能只是行业特征 |
| **暂未识别现金流风险** | 全部 10 项指标处于正常或数据不足 | 如果大量指标为"数据不足"，说明输入数据不够，结论有局限 |

### 常见误判场景

**场景 1：SaaS 公司被误判为"预警"**

SaaS 公司在高速增长期经营现金流为负是常态（获客成本前置、年合同制）。如果 R9（行业对标）显示偏离不大，且 R5（现金跑道）充裕，那么 R0 的"预警"不一定是致命问题。关注 R1（盈利质量）——如果 CF/NI 背离也很严重，才是真正的红旗。

**场景 2：地产公司被误判为"预警"**

地产公司天然高杠杆、长 CCC。如果 R8（偿债能力）触发预警但 R9 显示与行业基准偏离不大，说明这只是行业特征而非公司特有问题。但如果 R8 触发预警且行业对标也严重偏离（如负债/现金是行业基准的 5 倍），则需要高度警惕。

**场景 3：数据不足 ≠ 没有问题**

如果大量指标显示"数据不足"（例如只提供了核心 4 字段），结论"暂未识别现金流风险"的置信度很低。建议尽可能多地提供扩展字段以获得完整的 10 维覆盖。

### 与 orchestrator 的配合

本 skill 的 `check_risk()` 返回的 `has_risk` 和 `overall_risk` 可以直接被 orchestrator 用于计算现金流维度的分数：

- `overall_risk == "正常"` → 现金流维度高分（80-100）
- `overall_risk == "关注"` → 现金流维度中分（50-70）
- `overall_risk == "预警"` → 现金流维度低分（20-40）

`calculate_runway()` 的跑道月数和敏感性数据可用于更精细的评分调整。
